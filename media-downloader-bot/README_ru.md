# TikTokDownloaderBot
*[English version](README.md)*

Telegram-бот, который тащит видео/аудио с YouTube, TikTok, Instagram и Pinterest и отдаёт файлом — либо просто кинул ссылку в чат, либо через inline-режим (`@твой_бот <ссылка>` буквально в любом чате).

Собран на `aiogram 3`, `yt-dlp` и `ffmpeg` для нарезки клипов.

## Что реально умеет

- Кидаешь ссылку → бот отвечает кнопками: **Видео / Аудио (MP3) / клип 30 сек**. Тапаешь — качает и присылает файл. Никакого автоскачивания на каждую ссылку в чате — бот просто предлагает, а решаешь ты.
- То же самое работает inline: набираешь `@твой_бот <ссылка>` в любом чате (даже там, где бота нет) — те же три варианта прямо в inline-результатах.
- Загрузки идут через очередь с пулом воркеров (`asyncio.Queue` + фиксированное число воркеров) — если пять человек одновременно закинут ссылки, сервер не захлебнётся от пяти параллельных `yt-dlp`/`ffmpeg`.
- TikTok обрабатывается отдельно: вместо борьбы с антибот-защитой yt-dlp на каждый запрос бот сначала стучится в API [tikwm.com](https://tikwm.com) (обычный HTTP-запрос, без капчи) и откатывается на yt-dlp только если tikwm недоступен.
- Есть скрытая команда `/debug <ссылка>` (только для админа) — гоняет yt-dlp в verbose-режиме и присылает лог файлом. Полезно, если хостинг такой, что "консоль" — это просто вывод бота, и `yt-dlp -vU` руками не запустишь.

## Что нужно перед запуском

- Python 3.11+
- Установленный `ffmpeg` (именно бинарник, не pip-пакет). `apt install ffmpeg` на Debian/Ubuntu, `brew install ffmpeg` на Mac.
- Токен бота от [@BotFather](https://t.me/BotFather).

```bash
python -m venv venv
source venv/bin/activate   # на Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Дальше:

```bash
cp .env.example .env
```

Открой `.env` и впиши хотя бы `BOT_TOKEN`. У всего остального есть адекватные значения по умолчанию — смотри комментарии в `.env.example`.

Запуск:

```bash
python main.py
```

## Настройка inline-режима (тут есть нюансы)

Для inline-режима нужно включить две вещи в BotFather, которые по умолчанию выключены:

1. **Сам inline-режим** — обычно уже включён, если BotFather при создании бота показал inline-плейсхолдер. Если нет: `/setinline`.
2. **Inline feedback** — `/setinlinefeedback` → выбрать бота → **100%**. Без этого Telegram вообще не сообщает боту, какой вариант выбрал пользователь (событие `chosen_inline_result` просто не приходит), и плейсхолдер "⏳ загружаю..." так и висит, выглядя как баг. На этом моменте залипают чаще всего.

Ещё один нюанс API Telegram, о котором стоит знать: когда редактируешь inline-сообщение, чтобы подменить плейсхолдер на настоящее видео, Telegram **не даёт загрузить свежий файл с диска** для такого редактирования — только файл, у которого уже есть `file_id` (то есть однажды уже отправленный через бота), либо прямую ссылку. Поэтому обходной путь такой: бот скачивает файл, тихо отправляет его в чат, который сам контролирует (`STORAGE_CHAT_ID`, а если не задан — берётся `ADMIN_ID`), чтобы получить `file_id`, удаляет эту копию, и уже этим `file_id` подменяет плейсхолдер в inline-сообщении. Итог: в чат, указанный как "хранилище", будет на секунду залетать копия всего, что кто-либо скачивает через inline-режим. Это ожидаемое поведение, не баг — просто выбери чат, в котором тебе это не мешает (проще всего — личка с самим ботом).

## Переменные окружения, все

| Переменная | Что делает |
|---|---|
| `BOT_TOKEN` | токен от BotFather, обязательна |
| `MAX_WORKERS` | сколько загрузок идёт параллельно |
| `QUEUE_MAX_SIZE` | сколько задач может ждать в очереди, прежде чем начнёт отвечать "попробуйте позже" |
| `MAX_VIDEO_HEIGHT` | ограничение качества скачивания, например 1080 |
| `DOWNLOAD_DIR` | временная папка для загрузок, чистится после каждой отправки |
| `ADMIN_ID` | твой числовой Telegram id, открывает `/debug` и по умолчанию используется как чат-хранилище |
| `STORAGE_CHAT_ID` | отдельный чат для трюка с `file_id` в inline-режиме, если не хочешь смешивать с ADMIN_ID |
| `TIKTOK_BACKEND` | `auto` (tikwm → откат на yt-dlp), `tikwm`, или `ytdlp` |
| `COOKIES_FILE` | путь к `cookies.txt` (формат Netscape) — иногда нужен, если источник начал банить капчей IP твоего хостинга |
| `PROXY_URL` | прокси для запросов yt-dlp, если IP хостинга заблокирован целиком |

Свой числовой Telegram id можно узнать у [@userinfobot](https://t.me/userinfobot).

## Про лимит Telegram в 50 МБ

Обычные боты (не self-hosted Bot API сервер) не могут отправлять файлы больше 50 МБ. Если видео слишком тяжёлое, бот честно об этом скажет, а не просто молча зависнет. Если такие файлы нужны регулярно — придётся поднимать свой [Bot API сервер](https://github.com/tdlib/telegram-bot-api).

## TikTok иногда ломается сам по себе — это нормально

TikTok достаточно часто меняет сайт/API, так что экстрактор TikTok в yt-dlp периодически ломается, чинится, потом снова ломается. Если TikTok-ссылки перестали качаться:

1. Обнови yt-dlp: `pip install -U yt-dlp`. Не помогло — попробуй nightly-сборку, фиксы обычно попадают туда первыми: `pip install -U --pre yt-dlp`.
2. Этот бот в любом случае сначала пробует tikwm.com (см. `TIKTOK_BACKEND`), что обходит большинство таких поломок — это отдельный сервис, который уже сам разрешил видео на своей стороне, так что сломанный экстрактор TikTok в yt-dlp не важен, пока не упал ещё и tikwm.
3. Команда `/debug <ссылка>` даст нормальный лог ошибки без доступа к консоли хоста.

Не стоит зашивать в опции экстрактора ручные фиксы под конкретный TikTok API (хостнеймы и т.п.) — они устаревают быстрее, чем успевают помочь, и в итоге чинишь уже свой собственный патч, а не реальную проблему.

## Про legal

Бот качает контент с площадок, чьи условия использования это, как правило, не приветствуют (YouTube, Instagram, TikTok, Pinterest). yt-dlp и tikwm сами по себе легальные инструменты/сервисы, а вот что делать с тем, что они скачали — личный архив или раздача чужих видео широкой публике — уже на твоей совести. Пользуйся с умом.

## Структура проекта

```
main.py              # точка входа, всё собирает вместе
config.py             # тут живут переменные окружения
queue_manager.py       # ограниченная асинхронная очередь + пул воркеров
downloader.py           # yt-dlp / tikwm / ffmpeg, вся логика скачивания
pending.py               # хранилище коротких id для callback_data / inline result id (у обоих лимит 64 байта)
handlers/
  direct.py               # обычный чат: ссылка → кнопки → скачивание
  inline.py                # inline-режим: запрос → варианты → chosen_inline_result → скачивание
```
Удачи в использовании!
